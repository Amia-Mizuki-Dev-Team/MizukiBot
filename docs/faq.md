# 常见问题与故障排查

本页只处理高频问题。指令、参数和权限范围仍以 Bot 内帮助菜单及对应功能文档为准。遇到服务维护或上游异常时，请先查看[功能状态与数据来源](/status)和[服务状态与公告](/service-announcements)。

## Bot 完全没有回复

先按以下顺序检查：

1. 确认群主已在机器人管理中开启“获取群内全部消息”。
2. 直接发送 `帮助`，不要先 @机器人。
3. 检查发送内容是否包含多余空格、错误前缀或不完整参数。
4. 换一个基础指令测试，例如 `个人信息` 或 `经济帮助`。
5. 查看服务公告，确认 Bot 是否正在重启、维护或迁移。

如果所有基础指令都没有响应，通常不是单个插件问题，而是 Bot 在线状态、群消息权限或平台链路异常。

## 为什么 @机器人后反而无法触发

当前群聊环境支持直接发送指令文本。部分功能在消息包含 @机器人时可能无法正确识别，因此优先直接发送：

```text
帮助
```

而不是：

```text
@Amia_晓山瑞希 帮助
```

群聊未开启全部消息权限时，实际触发方式以平台配置和 Bot 返回为准。

## 只有某一个功能不可用

先测试 `帮助` 或其他基础指令：

- 基础指令正常、只有某个模块失败：更可能是该插件、上游接口或数据源异常。
- 所有指令都失败：更可能是 Bot、群权限或平台链路异常。
- 同一指令偶尔成功：可能是上游超时、请求排队或平台发送限制。

不要在短时间内连续重复发送大量相同指令。等待片刻后重试一次，并保留原始错误提示。

## PJSK 绑定或查询失败

检查以下项目：

- 游戏 ID 和区服前缀是否正确；
- 当前 QQ 是否已经绑定目标账号；
- 查询他人账号时，对方是否允许公开查询；
- 该功能是否要求账号验证、suite 数据或 MySekai 数据；
- 对应区服和上游服务是否暂时不可用。

常用区服前缀包括 `cn`、`tw`、`en` 和 `kr`。不同区服的支持范围不完全相同，以 Bot 实际返回为准。

::: warning 账号安全
绑定、验证或上传数据前，请自行保存引继码和密码。不要在公开群聊或反馈表单中提交引继信息、Token、登录二维码及其他账号凭证。
:::

## PJSK 基础查询能用，但进阶功能不能用

Rating、查榜、组卡、详细账号数据和 MySekai 等功能可能依赖额外数据：

- suite 数据未上传或已经过期；
- MySekai 数据尚未上传；
- 账号尚未完成验证；
- 当前区服不支持该项能力；
- 上游后端暂时未返回完整数据。

可以先使用 `抓包数据`、`烤森抓包数据` 或验证列表相关指令检查当前数据状态。上传入口和详细要求见 [PJSK 专项功能](/features/pjsk)。

## 舞萌 DX 的 B50、AP50 或查歌失败

先确认：

1. 已绑定可用的数据源账号；
2. 默认数据源设置正确；
3. 数据源授权没有失效；
4. 当前查询目标确实存在成绩数据；
5. 落雪、水鱼或相关上游服务没有异常。

可以尝试 `查看绑定`、`切换数据源 落雪` 或 `切换数据源 水鱼`。查询和分析功能由舞萌插件处理，成绩上传则由独立同步组件处理，两者故障范围不同。

## 舞萌 DX 成绩同步一直排队或没有更新

成绩同步服务当前存在固定维护窗口，**每日 00:00—11:00 暂停服务**。维护时间内无法正常同步不代表账号损坏。

其他常见原因：

- 队列中已有其他用户；
- 当前会话未完成或异常退出；
- 落雪 OAuth 授权码过期；
- 水鱼 Token 无效；
- 上传后数据源尚未完成处理。

建议依次使用：

- `队列状态`：查看排队情况；
- `查看绑定`：确认账号和同步类型；
- `取消`：取消当前流程；
- `登出`：清理异常登录状态；
- `上传成绩`：在维护窗口外重新开始。

完整流程见[舞萌 DX 专项](/features/maimai)。

## 群活统计与群聊分析为什么不一致

这两类功能不是同一套数据：

- `今日发言`、`本月发言`、`全群统计` 等属于基础消息活动统计；
- 群聊活跃分析属于独立分析组件，需要管理员在目标群主动开启后才开始记录。

群聊分析不会补算启用前的数据，也不默认采集所有群。因此，两个模块的时间范围和统计口径可能不同。

## 群聊分析会保存聊天内容吗

群聊活跃分析默认不开启。管理员在目标群主动开启后，才会记录之后产生的匿名活动元数据，用于消息量、发言用户数和基础活跃摘要。

该组件的公开边界是：

- 不保存消息正文；
- 不保存昵称；
- 不保存真实 QQ 号；
- 不保存虚拟用户 ID 或群 ID 明文；
- 不采集图片、语音、文件内容；
- 不采集私聊内容。

具体启用状态以目标群管理员配置为准。

## 管理员指令提示无权限

可能原因包括：

- 当前事件没有正确识别管理员身份；
- 指令要求群主、管理员或 Bot 超级用户权限；
- QQ 官方 Bot 返回的是平台虚拟身份；
- 权限服务异常时采用默认拒绝策略；
- 当前群没有启用对应模块。

不要反复尝试绕过权限。请由群主或维护人员确认群权限、绑定关系和 Bot 配置。

## 图片、菜单或按钮没有显示

先判断文字回复是否正常：

- 文字正常、只有图片失败：可能是图片生成、上传、图床或 QQ 平台发送限制；
- Markdown 菜单缺少按钮：可能是当前客户端或官方 Bot 能力差异；
- 所有回复都没有：按“Bot 完全没有回复”处理。

反馈时请提供完整指令、发生时间、客户端类型和返回截图，不要只写“图片坏了”。

## 文档与 Bot 实际行为不一致

插件更新、兼容调整和生产部署之间可能存在短时间差异。处理顺序如下：

1. 以 Bot 当前返回和 Bot 内帮助菜单为准；
2. 查看[功能状态与数据来源](/status)；
3. 查看[Bot 更新日志](/features/bot_update)和[服务状态与公告](/service-announcements)；
4. 确认属于稳定差异后再提交反馈。

## 仍未解决时如何反馈

提交前请准备：

- 问题发生的日期和大致时间；
- 使用的群聊环境；
- 完整指令和参数；
- Bot 返回的文本、图片或错误提示；
- 完整操作步骤；
- 是否可以稳定复现；
- 已遮挡账号、Token、二维码等敏感内容的截图。

整理完成后前往[问题反馈](/feedback)。缺少指令、时间和原始错误内容时，通常无法有效定位问题。
