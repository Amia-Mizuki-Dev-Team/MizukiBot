# 问题反馈

为了缩短定位时间，请在提交前确认问题能够稳定复现，并尽量提供完整上下文。

<DocCallout title="不要提交敏感信息" type="warning">
账号凭证、Token、登录二维码、Cookie、完整身份信息和其他敏感内容不得提交到公开表单。截图中出现这些内容时，请先遮挡。
</DocCallout>

## 提交前检查

<div class="amia-feedback-checklist">
  <div class="amia-feedback-item"><strong>发生时间</strong>提供日期和大致时间，便于对应服务日志。</div>
  <div class="amia-feedback-item"><strong>运行环境</strong>说明群聊环境、Bot 实例，以及是否为 QQ 官方 Bot。</div>
  <div class="amia-feedback-item"><strong>完整指令</strong>保留实际发送的指令、参数、空格和前缀。</div>
  <div class="amia-feedback-item"><strong>实际结果</strong>提供 Bot 返回的文本、图片或错误提示。</div>
  <div class="amia-feedback-item"><strong>复现步骤</strong>从开始操作到问题出现，按顺序说明每一步。</div>
  <div class="amia-feedback-item"><strong>复现概率</strong>说明问题是否稳定出现，或只发生过一次。</div>
</div>

## 故障反馈模板

复制以下模板并补充内容：

```text
问题描述：
发生时间：
群聊环境与 Bot 实例：
实际发送的指令：
复现步骤：
预期结果：
实际结果：
是否可以重复出现：
相关截图或日志：
```

## 功能建议应包含

- 需要解决的具体使用问题；
- 预期的操作流程和返回结果；
- 现有功能为何无法满足需求；
- 是否涉及管理员权限、用户数据或第三方服务。

<DocCallout title="提交质量">
描述越具体，问题越容易被复现和处理。只有“不能用”“报错了”等结论，通常不足以定位问题。
</DocCallout>
